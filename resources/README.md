# 3D 模型測試資源

本資料夾集中保存使用者提供的原始 OBJ、MTL、貼圖與 STL，供編輯器本機匯入、材質比較及部件選取測試使用。原檔按位元組複製，未修改幾何、材質、檔名或資料夾內的相對路徑。

## 檔案位置

| 位置 | 內容 |
| --- | --- |
| `obj/MO01/` 至 `obj/MO09/` | 每個型號各有一組 OBJ＋MTL |
| `obj/MO12/` 至 `obj/MO14/` | 每個型號各有一組 OBJ＋MTL |
| `obj/MO09/` | 另含 `bump_cross_hatch.png` 凹凸貼圖 |
| `obj/MO13/`、`obj/MO14/` | 各含 `FabricWool001_COL_VAR1_HIRES.jpg` 與 `FabricWool001_NRM_HIRES.jpg` |
| `stl/` | `40.stl`、`41.stl`、`内径12mm合金圈.stl` |

合計 12 個 OBJ、12 個 MTL、5 張貼圖與 3 個 STL，共 32 個資源檔。未收到 MO10、MO11。

## 在編輯器匯入

1. 點「開啟 OBJ／STL／MTL」，同時選取同一型號的 OBJ、MTL，以及該模型需要的貼圖；也可點「匯入模型資料夾」，選取整個型號資料夾。
2. 比較 MO06 有沒有材質：先只選 `obj/MO06/MO06.obj`，再重新同時選取 `MO06.obj` 和 `MO06.mtl`。前者可能顯示 `Missing MTL: MO06.mtl` 並使用編輯器的表面處理；後者預設使用原檔材質。
3. 已開啟 OBJ 後，可再次點「開啟 OBJ／STL／MTL」，只選 `MO06.mtl` 補入材質，無需重新選 OBJ。MTL 不包含模型形狀；沒有 OBJ 或目前是 STL 時會顯示提示。材質名稱不匹配時會保留原本模型和外觀。
4. 成功補入後，編輯器會切到「原始材質」，顯示已載入的 MTL 檔名；原本的部件、尺寸與設計修改保持不變。MO06 的 MTL 定義灰銀色與接近白色的材質，沒有外部圖片貼圖，亦不會新增模型部件。
5. STL 可單獨選取；標準 STL 主要保存三角形幾何，不搭配 MTL。

本機匯入供當前編輯器預覽，不會自動寫入產品資料庫或部署到伺服器。

## 原始來源與完整性

- OBJ、MTL、貼圖：由使用者提供的「配料建模 layering adjusted.zip」解壓資源整理，來源備份保留在專案 `.deploy/source-models/obj/`。
- STL：由工作區同層 `stlobj/` 複製。
- `manifest.json` 記錄每個資源的相對路徑、檔案大小與 SHA-256，便於檢查複製或傳送後是否完整。

依專案大型模型管理規範，`obj/` 和 `stl/` 保存在本機，已排除於 Git、Docker 建置內容及 `make package` 部署包；Git 可記錄本說明、忽略規則和檔案清單。其他開發者取得資源後，按清單放回對應路徑即可。
